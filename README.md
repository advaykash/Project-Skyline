# OrbitWatch

**Explore Earth. Find a satellite. Inspect its real orbital elements. Understand its calculated position. Visualize its orbit. Trust what the application tells you.**

OrbitWatch is a satellite-tracking and orbital-visualization application built on **genuine CelesTrak General Perturbations data** and **SGP4** propagation. Every satellite marker on the globe is a real catalogue object, propagated from published orbital elements with a validated coordinate pipeline — and every number in the interface is labelled with where it came from: published element, calculated state, or derived property.

Built for the PHS Hackathon (repository: `akulbajpai-code/SkyLine` — see [Branding](#branding)).

---

## Quick start

Requirements: Node.js ≥ 20 (tested on 22).

```bash
npm install
npm run build          # typecheck + production build into dist/
npx wrangler pages dev dist --port 8788 --ip 0.0.0.0
# open http://localhost:8788
```

That single `wrangler pages dev` process serves the frontend **and** the real Cloudflare Pages Functions API — the same runtime that ships to production.

For frontend iteration you can instead run the Vite dev server (`npm run dev`) with the API separately (`npm run dev:api`); the dev server proxies `/api` to the Pages runtime on port 8788.

## What it does

- **Interactive 3D Earth** (Three.js) with a real day/night terminator, night lights, ocean specular, clouds, atmospheric limb and a procedural starfield. Bundled NASA-derived textures; graceful fallback if any asset fails.
- **Real catalogues** — 9 CelesTrak groups bundled offline (~30,500 objects: space stations, brightest, active, Starlink, weather, science and three debris clouds), plus 4 additional groups served live when CelesTrak is reachable.
- **Search** over every loaded record: names, NORAD IDs, international designators, keyboard navigation.
- **Satellite inspector** that separates **source elements** (CelesTrak GP), **calculated position** (SGP4 at a stated instant) and **derived properties** (documented formulas), with units, datum notes and element-age warnings.
- **Orbit path & ground track** generated by the same propagation + frame transforms as the markers, with the antimeridian handled correctly.
- **Simulation clock** with playback rate, seek and "Now" — globe, markers, orbit and the displayed timestamps always refer to the same instant.
- **Honest data states**: `live` / `cached` / `stale` / `snapshot`, derived from actual retrieval metadata — never hardcoded. If CelesTrak cannot be reached, the app says so and shows the real capture time of the data it is serving.

## Architecture

```
CelesTrak GP JSON ──► Cloudflare Pages Function /api/gp ──► cache (Cache API)
        │                     │  validation · allowlist · timeout · retry      │
        │                     ▼                                                ▼
        │              catalog records (verbatim) ──► propagation worker (SGP4)
        │                     │                            │
        └── offline snapshot  │                            ▼
            (data/snapshot)   ▼                     TEME ──gmst──► ECEF ──► Three.js scene
                          React UI (search · inspector · data health · time)
```

| Layer | Where | Notes |
|---|---|---|
| Frontend | `src/` (React + Vite) | No UI framework; small observable store (`src/state/`) |
| 3D scene | `src/globe/` | Three.js; one draw call for the whole catalogue |
| Orbital math | `src/orbital/` | satellite.js SGP4; frames, derived values, orbit/ground-track generation |
| Propagation worker | `src/workers/propagator.worker.ts` | Off-main-thread catalogue propagation |
| API | `functions/api/` (Cloudflare Pages Functions) | `/api/health`, `/api/gp`; same code is unit-tested |
| Data | `data/snapshot/` | Verbatim CelesTrak GP JSON + SHA-256 provenance manifest |
| Shared contracts | `shared/` | Group registry, freshness policy, API types |

**Frame & unit conventions** (the full statement lives in `src/orbital/constants.ts`): SGP4 outputs TEME; Earth rotation is applied exactly once (GMST) to reach ECEF; the Three.js scene is Earth-fixed with `scene = (ecef.x, ecef.z, −ecef.y)`, one scene unit = 6371 km. Latitudes/altitudes are WGS-84 geodetic; orbit-shape parameters follow the WGS-72 constants SGP4 is defined on.

## Data model & honesty rules

The API derives one of four states from metadata (see `shared/freshness.json`):

| State | Meaning |
|---|---|
| **live** | CelesTrak fetched within the freshness window (2 h) |
| **cached** | genuine CelesTrak data ≤ 24 h old (a refresh was attempted and failed) |
| **stale** | genuine CelesTrak data older than 24 h, still served, clearly marked |
| **snapshot** | the bundled offline dataset — genuine records, never current |

- Records are never edited, synthesised or reordered. Each group file's SHA-256 is recorded in `data/snapshot/manifest.json`.
- A failed propagation produces **no position** — never invented coordinates.
- Positions are SGP4 **predictions** from published elements; the inspector states element age and an along-track drift estimate so users can judge prediction quality.

## Testing

```bash
npm test               # 70 unit/integration tests (vitest)
npm run typecheck      # tsc --noEmit
npm run lint           # eslint
npm run build          # production build
CHROME_PATH=/path/to/chromium npm run test:e2e   # real-browser end-to-end (needs a running server)
node scripts/verify-live.mjs                      # genuine CelesTrak connectivity check (needs internet)
```

The scientific core is verified against an **independent implementation**: `tools/skyfield-reference.py` re-propagates the same element sets with Python's canonical Vallado SGP4 and skyfield's geodetic solution; `tests/orbital-reference.test.ts` compares this application's pipeline against those reference states (20 comparisons, documented tolerances). See `docs/TESTING.md` for the full matrix and the live-path verification procedure.

## Deployment (Cloudflare Pages)

```bash
npm run build
npx wrangler pages deploy dist        # from a machine with Cloudflare credentials
```

or connect the repository in the Cloudflare Pages dashboard: build command `npm run build`, output directory `dist`. The `functions/` directory is deployed automatically. No paid resources are required (no KV, no Durable Objects — caching uses the Cache API). Full guide: `docs/DEPLOY.md`.

## Limitations (honest)

- Positions are SGP4 predictions, not tracking observations. Accuracy degrades with element age (shown in the UI) and space weather.
- The bundled snapshot groups were captured at different times (see `data/snapshot/manifest.json`); groups marked **snapshot** are not current.
- The API rate limit is per-isolate (documented backstop, not a global quota).
- Cache API storage is per-data-centre and best-effort; a cold cache simply triggers a fresh fetch.
- In this development sandbox, outbound access to `celestrak.org` is blocked, so the live-retrieval path was verified with deterministic tests and a real runtime, while `scripts/verify-live.mjs` covers the genuine connectivity check on a machine with internet access (see the final report for exactly what was and was not verified here).
